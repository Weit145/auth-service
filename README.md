
# 🔐 Auth Service

**Auth Service** — микросервис аутентификации и авторизации для платформы форума.
Он управляет регистрацией пользователей, входом в систему и проверкой прав доступа через JWT. Сервис взаимодействует с другими компонентами платформы через **gRPC** и события **Kafka**, без прямого HTTP-доступа извне.

Auth Service является частью проекта сайта **[Microservices_Site](https://github.com/Weit145/microservices_site)**. 




## 🎯 Основные функции

1.  **Регистрация и верификация:**
    *   `CreateUser`: Создание неактивного пользователя в базе данных.
    *   Отправка события в Kafka (`registration` topic) для отправки email с верификационным JWT.
    *   `RegistrationUser`: Активация пользователя после перехода по ссылке с верификационным токеном.

2.  **Аутентификация:**
    *   `Authenticate`: Вход по логину и паролю.
    *   `RefreshToken`: Обновление access-токена с помощью refresh-токена.
    *   `LogOutUser`: Выход пользователя из системы.

3.  **Авторизация и информация о пользователе:**
    *   `CurrentUser`: Предоставление информации о текущем пользователе на основе access-токена.

4.  **Управление жизненным циклом JWT:**
    *   **Access Token:** Краткоживущий токен для доступа к защищенным ресурсам.
    *   **Refresh Token:** Долгоживущий токен для обновления access-токена, хранится в HttpOnly cookie.
    *   **Email Verification Token:** Токен для подтверждения адреса электронной почты.

## 🏛️ Архитектура

Сервис построен с использованием принципов **Domain-Driven Design (DDD)**, что отражено в структуре каталога `src`:
- **`domain`**: Содержит бизнес-сущности (Entities), доменные события (Events) и репозитории. Это ядро бизнес-логики.
- **`application`**: Оркестрирует выполнение бизнес-логики, используя сервисы и обрабатывая DTO.
- **`infrastructure`**: Реализует внешние зависимости: работу с базой данных (SQLAlchemy), брокером сообщений (Kafka) и gRPC.

## 🌐 Взаимодействие с другими сервисами

*   **Предоставляет gRPC API** для **API Gateway**.

*   **Публикует события в Kafka** в топики:
    *   `auth`: для синхронизации создания пользователя с другими сервисами (например, `user-service`).
    *   `registration`: для отправки email с подтверждением регистрации (потребляется `task-service`).

*   **Потребляет события из Kafka** из топиков:
    *   `delete` и `admin_delete_user`: Для удаления пользователя, инициированного `user-service` или `admin-service`.
    *   `check_verified`: Для периодической очистки не верифицированных пользователей.
    *   `admin_ban_user`: Для блокировки (бана) пользователя по запросу от `admin-service`.

*   **Хранилище данных**: Использует собственную изолированную базу данных `postgres_auth`.

## 🛡️ Безопасность

* Вся логика аутентификации и авторизации централизована.
* JWT является основным механизмом авторизации.
* gRPC-контракты описаны в каталоге `proto`.
* Пароли хранятся безопасно с использованием Argon2 через `argon2-cffi` и `passlib`.
* Интеграция с Kafka используется для событийной синхронизации с другими сервисами.
